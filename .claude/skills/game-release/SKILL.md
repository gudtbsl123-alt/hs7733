# 게임 마무리: 소개글 + 스크린샷 8~10장 + 교실 TV 안내판

결과물은 `release/<게임이름>/` 폴더에 모은다.
- `소개글.md` — 웹사이트에 붙여 넣을 소개글
- `screenshots/01_시작화면.png` ~ 마지막 `결과창.png` (8~10장)
- `capture.js` — 이 게임용 캡처 스크립트 (다음에 다시 찍을 때 재사용)
- `screenshots/00_교실TV_게임안내.png` — 교실 TV에 띄울 "이것만 기억해요" 안내판 (1920×1080)
- `tv_guide.json` — 안내판 문장 (고쳐서 다시 만들 때 재사용)

작업이 끝나면 소개글 전문을 대화창에도 그대로 보여 준다 (선생님이 바로 복사할 수 있게).

---

## 1단계: 게임 파일에서 사실 뽑기 (필수)

기억이나 대화 맥락으로 문제·정답·수치를 쓰지 않는다. **반드시 게임 HTML을 읽어서** 확인한다.
- 문항 수, 난이도 구분, 전 문항의 문제와 정답
- 조작 키·버튼 (이벤트 리스너에서 실제 키 이름 확인)
- 캐릭터·아이템 종류 수, 가격·보상 수치, 해금 조건
- 저사양 모드, 저장·이어하기, 배경음악 유무

파일에 없는 숫자는 쓰지 않는다.

## 2단계: 소개글 작성

아래 순서와 이모지를 그대로 쓴다.

```
🎯 게임 목적
📝 내용과 특징
🎮 조작 및 가이드
❓ 모든 문제와 정답
💡 플레이팁
================================================================

<학생 공유 방법 2가지>

1. HTML 파일 학생 공유
2. 아래 사이트 공유
   https://gudtbsl123-alt.github.io/hs7733/
```

- **🎯 게임 목적**: 2~3문장. 학년·학기·단원명을 정확히 쓰고, 단원을 복습하며 무엇을 달성하는 게임인지 요약.
- **📝 내용과 특징**: 불릿 8~12개. 수학(교과)이 게임과 어떻게 맞물리는지를 맨 앞에. 문항 수·셔플 여부, 보상·해금 구조 수치, 콘텐츠 분량, 저장·배경음악·저사양 모드.
- **🎮 조작 및 가이드**: 불릿 6~8개. 필수 시작 순서는 ①②③으로 맨 앞에. 마우스 / 키보드 / 터치를 각각. 취소·되돌리기 방법. 마지막 줄에 PC·태블릿·휴대폰 지원 여부.
- **❓ 모든 문제와 정답**: 표 `번호 | 문제 | 정답`. 난이도가 나뉘면 `[난이도: 하 (기초)]` 소제목으로 표를 나눈다. 전 문항 빠짐없이, 지문은 게임 문장 그대로(HTML 태그만 제거).
- **💡 플레이팁**: 불릿 6~9개. 모르면 손해 보는 것 위주. 점수 요령, 틀렸을 때 어떻게 되는지, 초반 공략, 놓치기 쉬운 기능, 학교 PC가 느릴 때 저사양 모드, 수업 끝날 때 저장.

문체: '~합니다'체, 담백하게. **굵게**는 단원명·필수 순서·저사양 모드·핵심 수치에만. 과장 광고 문구 금지. 게임 속 용어를 그대로 쓴다.
공유 주소가 이 게임용으로 따로 있으면 알려 달라고 글 **끝에 한 줄로**만 덧붙인다.

## 3단계: 스크린샷 8~10장 캡처

1. 처음 한 번만 준비 (이미 되어 있으면 건너뜀):
   - **Claude Code 웹(클라우드) 환경**에는 이미 준비돼 있다. 설치하지 말고 `NODE_PATH=/opt/node22/lib/node_modules`를 붙여 실행한다(브라우저는 `/opt/pw-browsers/chromium`, 스크립트가 알아서 찾는다).
   - 선생님 컴퓨터에서 처음 할 때만 저장소 **바깥** 폴더에서 설치한다. 저장소 안에 `node_modules`·`package.json`을 만들지 않는다(GitHub Pages 사이트에 올라가 버린다).
   ```
   npm install -g playwright
   npx playwright install chromium
   ```
2. `scripts/capture_template.js`를 `release/<게임이름>/capture.js`로 복사한다.
3. 게임 코드를 읽고 **과목과 보스전 유무를 먼저 확인한 뒤**, 닉네임(`NICKNAME`)과 시나리오 부분을 채운다.
4. 실행: `NODE_PATH=/opt/node22/lib/node_modules node release/<게임이름>/capture.js "<게임.html>" release/<게임이름>/screenshots` (선생님 컴퓨터에서는 `NODE_PATH=…` 없이)
5. 찍힌 사진을 **전부 직접 열어 보고** 확인한 뒤, 문제가 있으면 시나리오를 고쳐 다시 찍는다.

### 닉네임: "장도초 ㅇㅇ천재"
게임 내용을 분석해 과목명을 넣는다. 예) 장도초 국어천재, 장도초 수학천재, 장도초 사회천재, 장도초 과학천재, 장도초 영어천재, 장도초 도덕천재
여러 과목이 섞였으면 비중이 가장 큰 과목으로 한다.

### 사진 구성
| 순서 | 장면 | 장수 |
|---|---|---|
| 1 | 시작 첫 화면 — 닉네임 칸에 "장도초 ㅇㅇ천재" 입력된 상태 | 1장 |
| 2 | 초반 플레이 | 2장 |
| 3 | 중반 플레이 | 2장 |
| 4 | 후반 플레이 | 2장 |
| 5 | 보스전 (**게임에 보스전이 있을 때만**) | 1~2장 |
| 6 | 게임 클리어 최종 결과창 | 1장 |

- 보스전이 없으면 8장, 있으면 9~10장이 된다. 보스전은 게임 흐름상 실제로 나오는 위치(보통 후반 다음)에 넣는다.
- 초반·중반·후반 각 2장은 **①문제만 보여 주는 화면 1장 + ②오답을 골라 힌트가 뜬 장면 1장**을 기본으로 한다. 게임에 힌트 기능이 없으면 ②는 오답 피드백 화면으로 대신한다.
- 보스전이 2장이면 보스 등장 화면 1장 + 보스와 문제를 푸는 장면 1장으로 한다.

### 시나리오 작성 요령
- 정답은 게임 코드의 문제 데이터에서 찾아 클릭한다. 오답 화면은 일부러 틀린 보기를 누른다.
- 중반·후반까지 빨리 가려면 정답을 연속으로 누르며 진행하고, 필요한 장면에서만 `shot()`을 부른다.
- 캔버스 게임은 `page.keyboard.press()` / `page.mouse.click(x, y)`로 조작한다. 오래 걸리면 `page.evaluate()`로 게임 변수(단계, 점수 등)를 조정해 해당 장면으로 이동해도 된다. 단, 화면에 보이는 내용이 실제 게임과 달라지면 안 된다.
- 연출이 긴 장면은 `shot('이름', 1500)`처럼 대기 시간을 늘린다.
- 파일 이름은 `02_초반_문제`, `03_초반_오답힌트`, `08_보스전`처럼 장면을 알 수 있게 짓는다.
- 스크립트가 게임 오류를 보고하면 스크린샷보다 **오류를 먼저 선생님께 알린다.**

## 3-2단계: 교실 TV 안내판 1장 ("이것만 기억해요")

목적은 교실 TV에 띄워 두고 **뒷자리 학생도 한눈에 읽고 바로 플레이하게 돕는 것**이다. 게임의 핵심 내용과 조작 팁을 **5개, 각각 한 문장**으로 만든다.

1. 게임 코드에서 실제 조작 키·규칙·수치를 확인한다(1단계에서 뽑은 사실만 쓴다).
2. `release/<게임이름>/tv_guide.json`을 만든다.
   ```json
   {
     "badge": "5학년 2학기 국어 · 2단원",
     "title": "말이 되는 섬",
     "accent": "#fdba74",
     "background": "screenshots/02_초반_문제.png",
     "items": ["문장1", "문장2", "문장3", "문장4", "문장5"],
     "footer": "맨 아래 한 줄 (선택)"
   }
   ```
   - `accent`: 게임 대표 색으로, 제목 색이 된다.
   - `background`: 흐리게 깔 게임 화면이다. 방금 찍은 스크린샷 중 하나를 고른다.
3. 실행: `NODE_PATH=/opt/node22/lib/node_modules node .claude/skills/game-release/scripts/make_tv_guide.js release/<게임이름>/tv_guide.json release/<게임이름>/screenshots/00_교실TV_게임안내.png`
4. 스크립트가 글자 크기(48px에서 시작, 넘치면 42px까지)를 맞추고 점검 결과를 알려 준다. **⚠ 경고가 나오면 문장을 줄여 다시 만든다.** 만든 그림은 직접 열어 확인한다.

### 5문장 쓰는 법
- **순서:** ① 기본 조작 → ② 정답을 내는 방법(게임의 핵심 규칙) → ③ 보조 규칙이나 표시 읽는 법 → ④ 틀렸을 때 / 막혔을 때 → ⑤ 보상·점수·보너스
- **한 문장, 한 줄:** 한글 30자 안팎. 설명하지 말고 **"무엇을 하면 → 무엇이 된다"**로 쓴다. 예: "정답 블록을 **빈칸 바로 아래**까지 밀고 → **위로 한 번 더!**"
- **초등학생 말투:** "~해요", "~돼요". 게임 속 용어를 그대로 쓴다.
- **키는 키 모양으로:** `[[스페이스]]`, `[[↑]]`, `[[Z]]`. 터치 전용 게임이면 "화면 왼쪽 누르기"처럼 쓴다.
- **강조는 한 문장에 1~2곳만:** `**정답 문**`(빨강). 방향·종류를 색으로 구분할 때는 `{파랑:위 문}` `{초록:가운데 문}` `{주황:아래 문}`을 쓴다.
- **이모지는 게임에 실제로 나오는 것만** 쓴다(❤️ 🪙 👾 등).
- **맨 아래 한 줄(footer):** 5문장에 못 넣은 것 하나(긴 문제 읽는 법, 보스 등장 등)를 쓴다. 없으면 비운다.

대화창에 다음을 짧게 보여 준다.
1. 소개글 전문
2. 스크린샷 목록(장수, 보스전 포함 여부, 사용한 닉네임)과 저장 위치, 교실 TV 안내판 5문장
3. 스크린샷과 안내판 그림을 파일로 보낸다
4. 확인이 필요한 점 (공유 주소, 발견한 게임 오류 등) — 있을 때만
