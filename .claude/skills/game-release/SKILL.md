# 게임 마무리: 게시판 소개글 + 스크린샷 8~10장 + 정답표 그림 + 교실 TV 안내판 + 번호 붙인 게시판 사진

결과물은 `release/<게임이름>/` 폴더에 모은다.
- `소개글.md` — 교사 커뮤니티(인디스쿨 등) 게시판에 올릴 글. 사진은 글 맨 위에 한꺼번에 올리고, 글은 그 아래에 쭉 이어 쓴다
- `게시판_사진/1번_….png` ~ `N번_정답표.png` — 게시글 맨 위에 올릴 사진. **올리는 순서대로 번호가 붙어 있어** 선생님은 1번부터 차례로 올리기만 하면 된다 (3-4단계)
- `screenshots/정답표.png` — 전 문항 정답을 담은 세로형 그림 1장 (게시글에 표 대신 넣는다)
- `answers.json` — 정답표 내용 (고쳐서 다시 만들 때 재사용)
- `screenshots/01_시작화면.png` ~ 마지막 `결과창.png` (8~10장)
- `capture.js` — 이 게임용 캡처 스크립트 (다음에 다시 찍을 때 재사용)
- `screenshots/00_교실TV_게임안내.png` — 교실 TV에 띄울 "이것만 기억해요" 안내판 (1920×1080)
- `tv_guide.json` — 안내판 문장 (고쳐서 다시 만들 때 재사용)

작업이 끝나면 소개글 전문을 대화창에도 그대로 보여 준다 (선생님이 바로 복사해 게시판에 붙일 수 있게).

---

## 1단계: 게임 파일에서 사실 뽑기 (필수)

기억이나 대화 맥락으로 문제·정답·수치를 쓰지 않는다. **반드시 게임 HTML을 읽어서** 확인한다.
- 문항 수, 난이도 구분, 전 문항의 문제와 정답
- 조작 키·버튼 (이벤트 리스너에서 실제 키 이름 확인)
- 캐릭터·아이템 종류 수, 가격·보상 수치, 해금 조건
- 저사양 모드, 저장·이어하기, 배경음악 유무

파일에 없는 숫자는 쓰지 않는다.

## 2단계: 소개글 작성 (게시판 · 수업 활용형)

선생님은 이 글을 **교사 커뮤니티 게시판**에 올린다. 읽는 사람은 대부분 **휴대폰**으로 보는 동료 교사이고, 가장 먼저 "우리 반 진도와 맞나, 어떻게 돌아가나"를 알고 싶어 한다. 그래서 **무엇을 배우는지를 맨 앞에**, 짧은 줄로 쓴다.

### 꼭 지킬 것 (예전 글이 길고 안 읽혔던 이유)
- **한 항목 = 휴대폰 한 줄(한글 20자 안팎).** 문장 대신 짧은 구로 쓴다. 3줄 넘는 불릿은 만들지 않는다.
- **표를 쓰지 않는다.** 특히 3칸 표는 휴대폰 폭을 넘어 잘린다. 정답은 본문에 쓰지 않고 **정답표 그림**(3-3단계)으로 넣는다.
- **문제 전문을 본문에 옮기지 않는다.**
- **사진은 글 사이에 끼우지 않는다.** 선생님이 게시글 맨 위에 사진을 한꺼번에 올리고, 글은 그 아래에 쭉 이어 쓴다.
  - 올리는 순서는 `게시판_사진/` 파일 번호가 정한다(3-4단계): 1번 시작 화면 → 2번 초반 문제 → 3번 오답 힌트 → 4번 결과창 → 5번 교실 TV 안내판 → 6번 정답표(세로로 길어서 맨 끝).
  - **글에서 사진을 가리키지 않는다.** "몇 번 사진", "위 사진", "N번 사진을 TV에 띄우기", "N번 사진에 정답" 같은 말을 쓰지 않는다. 글은 사진 없이도 읽히게 쓴다.
- 게시판 글쓰기 창은 마크다운을 읽지 않으므로 `**`, `#` 같은 기호를 쓰지 않는다. 소제목은 이모지로 구분한다.
- 전체 길이는 40줄 안팎.

### 양식 (이 순서와 이모지를 그대로)
```
제목: [🎮무설치 웹게임🎮][출판사 무관] <학년-학기> <과목> <단원 번호·단원명> - <게임 이름>

📚 이 게임으로 복습하는 것
<학년 학기 과목 단원> · <문항 수>문항
(학습지 N + 변형 N)            ← 해당할 때만

🔸 <소단원 또는 묶음 1> · N문항
· <구역·스테이지 이름>: <다루는 내용 2~3개>
· …

🔸 <묶음 2> · N문항
· …

🎮 게임 원리
<학생이 하는 일 → 그것이 답이 되는 방식 → 결과>   (한 줄)
<진행·해금 구조>                                   (한 줄)
틀리면 정답 대신 힌트 → 다시 도전                    (힌트가 있을 때)

🖱️ 조작
· 마우스·터치: …
· 키보드: …
· <놓치기 쉬운 조작 1개>
· PC·태블릿·휴대폰 지원 여부

💡 수업 팁                         ← 3~4줄
· 느린 PC → … → 저사양 모드
· 저장·이어하기
· 오답 노트 활용
· 배경음악 끄는 법(있을 때)

📥 학생 공유
① HTML 파일 그대로 나눠 주기 (인터넷 없이 실행)
② 사이트 링크: https://gudtbsl123-alt.github.io/hs7733/
```

- **📚 복습하는 것**이 글의 심장이다. 게임 속 구역·스테이지·난이도 묶음마다 **실제 문항에서 다루는 내용**을 2~3개씩 적는다(문항 데이터를 읽고 뽑는다). 묶음이 없는 게임은 문항을 주제별로 3~6줄로 묶는다.
- **🎮 게임 원리**는 "조작이 곧 학습"인 이유가 한눈에 보이게 화살표 한 줄로.
- 문체: 짧은 구 + 필요할 때만 '~해요'. 과장 광고 문구 금지. 게임 속 용어를 그대로 쓴다.
- 공유 주소가 이 게임용으로 따로 있으면 알려 달라고 대화창 보고 끝에 한 줄로만 묻는다(글에는 쓰지 않는다).
- 정답은 글에 쓰지 않고 정답표 그림을 사진 맨 끝에 올리는 것으로 대신한다(글에 정답표 안내 칸을 두지 않는다).

## 3단계: 스크린샷 8~10장 캡처

1. 처음 한 번만 준비 (이미 되어 있으면 건너뜀):
   - **Claude Code 웹(클라우드) 환경**에는 이미 준비돼 있다. 설치하지 말고 `NODE_PATH=/opt/node22/lib/node_modules`를 붙여 실행한다(브라우저는 `/opt/pw-browsers/chromium`, 스크립트가 알아서 찾는다).
   - 선생님 컴퓨터에서 처음 할 때만 저장소 **바깥** 폴더에서 설치한다. 저장소 안에 `node_modules`·`package.json`을 만들지 않는다(GitHub Pages 사이트에 올라가 버린다).
   ```
   npm install -g playwright
   npx playwright install chromium
   ```
2. `scripts/capture_template.js`를 `release/<게임이름>/capture.js`로 복사한다.
3. 게임 코드를 읽고 **과목과 보스전 유무를 먼저 확인한 뒤**, 닉네임(`NICKNAME`)과 시나리오 부분을 채운다.
4. 실행: `NODE_PATH=/opt/node22/lib/node_modules node release/<게임이름>/capture.js "<게임.html>" release/<게임이름>/screenshots` (선생님 컴퓨터에서는 `NODE_PATH=…` 없이)
5. 찍힌 사진을 **전부 직접 열어 보고** 확인한 뒤, 문제가 있으면 시나리오를 고쳐 다시 찍는다.

### 닉네임: "장도초 ㅇㅇ천재"
게임 내용을 분석해 과목명을 넣는다. 예) 장도초 국어천재, 장도초 수학천재, 장도초 사회천재, 장도초 과학천재, 장도초 영어천재, 장도초 도덕천재
여러 과목이 섞였으면 비중이 가장 큰 과목으로 한다.

### 사진 구성
| 순서 | 장면 | 장수 |
|---|---|---|
| 1 | 시작 첫 화면 — 닉네임 칸에 "장도초 ㅇㅇ천재" 입력된 상태. 타이틀 화면과 이름 쓰기 장면이 나뉜 새 게임은 이름 쓰기 장면에 입력한 상태로 찍는다 | 1장 |
| 2 | 초반 플레이 | 2장 |
| 3 | 중반 플레이 | 2장 |
| 4 | 후반 플레이 | 2장 |
| 5 | 보스전 (**게임에 보스전이 있을 때만**) | 1~2장 |
| 6 | 게임 클리어 최종 결과창 | 1장 |

- 보스전이 없으면 8장, 있으면 9~10장이 된다. 보스전은 게임 흐름상 실제로 나오는 위치(보통 후반 다음)에 넣는다.
- 초반·중반·후반 각 2장은 **①문제만 보여 주는 화면 1장 + ②오답을 골라 힌트가 뜬 장면 1장**을 기본으로 한다. 게임에 힌트 기능이 없으면 ②는 오답 피드백 화면으로 대신한다.
- 보스전이 2장이면 보스 등장 화면 1장 + 보스와 문제를 푸는 장면 1장으로 한다.

### 시나리오 작성 요령
- 정답은 게임 코드의 문제 데이터에서 찾아 클릭한다. 오답 화면은 일부러 틀린 보기를 누른다.
- 중반·후반까지 빨리 가려면 정답을 연속으로 누르며 진행하고, 필요한 장면에서만 `shot()`을 부른다.
- 캔버스 게임은 `page.keyboard.press()` / `page.mouse.click(x, y)`로 조작한다. 오래 걸리면 `page.evaluate()`로 게임 변수(단계, 점수 등)를 조정해 해당 장면으로 이동해도 된다. 단, 화면에 보이는 내용이 실제 게임과 달라지면 안 된다.
- 연출이 긴 장면은 `shot('이름', 1500)`처럼 대기 시간을 늘린다.
- 파일 이름은 `02_초반_문제`, `03_초반_오답힌트`, `08_보스전`처럼 장면을 알 수 있게 짓는다.
- 스크립트가 게임 오류를 보고하면 스크린샷보다 **오류를 먼저 선생님께 알린다.**

## 3-2단계: 교실 TV 안내판 1장 ("이것만 기억해요")

목적은 교실 TV에 띄워 두고 **뒷자리 학생도 한눈에 읽고 바로 플레이하게 돕는 것**이다. 게임의 핵심 내용과 조작 팁을 **5개, 각각 한 문장**으로 만든다.

1. 게임 코드에서 실제 조작 키·규칙·수치를 확인한다(1단계에서 뽑은 사실만 쓴다).
2. `release/<게임이름>/tv_guide.json`을 만든다.
   ```json
   {
     "badge": "5학년 2학기 국어 · 2단원",
     "title": "말이 되는 섬",
     "accent": "#fdba74",
     "background": "screenshots/02_초반_문제.png",
     "items": ["문장1", "문장2", "문장3", "문장4", "문장5"],
     "footer": "맨 아래 한 줄 (선택)"
   }
   ```
   - `accent`: 게임 대표 색으로, 제목 색이 된다.
   - `background`: 흐리게 깔 게임 화면이다. 방금 찍은 스크린샷 중 하나를 고른다.
3. 실행: `NODE_PATH=/opt/node22/lib/node_modules node .claude/skills/game-release/scripts/make_tv_guide.js release/<게임이름>/tv_guide.json release/<게임이름>/screenshots/00_교실TV_게임안내.png`
4. 스크립트가 글자 크기(48px에서 시작, 넘치면 42px까지)를 맞추고 점검 결과를 알려 준다. **⚠ 경고가 나오면 문장을 줄여 다시 만든다.** 만든 그림은 직접 열어 확인한다.

### 5문장 쓰는 법
- **순서:** ① 기본 조작 → ② 정답을 내는 방법(게임의 핵심 규칙) → ③ 보조 규칙이나 표시 읽는 법 → ④ 틀렸을 때 / 막혔을 때 → ⑤ 보상·점수·보너스
- **한 문장, 한 줄:** 한글 30자 안팎. 설명하지 말고 **"무엇을 하면 → 무엇이 된다"**로 쓴다. 예: "정답 블록을 **빈칸 바로 아래**까지 밀고 → **위로 한 번 더!**"
- **초등학생 말투:** "~해요", "~돼요". 게임 속 용어를 그대로 쓴다.
- **키는 키 모양으로:** `[[스페이스]]`, `[[↑]]`, `[[Z]]`. 터치 전용 게임이면 "화면 왼쪽 누르기"처럼 쓴다.
- **강조는 한 문장에 1~2곳만:** `**정답 문**`(빨강). 방향·종류를 색으로 구분할 때는 `{파랑:위 문}` `{초록:가운데 문}` `{주황:아래 문}`을 쓴다.
- **이모지는 게임에 실제로 나오는 것만** 쓴다(❤️ 🪙 👾 등).
- **맨 아래 한 줄(footer):** 5문장에 못 넣은 것 하나(긴 문제 읽는 법, 보스 등장 등)를 쓴다. 없으면 비운다.

## 3-3단계: 정답표 그림 1장

게시글의 정답 표는 휴대폰에서 잘리므로 **세로형 그림 한 장**(폭 900px)으로 만든다.

1. `release/<게임이름>/answers.json`을 만든다. **정답(a)은 게임 파일의 문제 데이터에서 코드로 뽑아 그대로 넣는다**(손으로 옮겨 적지 않는다). 사람이 쓰는 것은 문제를 한 줄로 줄인 `q`뿐이다.
   ```json
   {
     "badge": "4학년 2학기 사회 · 2단원",
     "title": "골목 민원 해결단",
     "accent": "#ffd04a",
     "groups": [
       { "name": "큰길 골목", "sub": "(1) 지역문제의 해결",
         "items": [ { "no": 1, "q": "문제를 한 줄로 줄인 말", "a": "정답 그대로" } ] }
     ],
     "footer": "맨 아래 한 줄 (선택)"
   }
   ```
   - `groups`는 게임 속 구역·스테이지·난이도 묶음을 따른다(소개글의 📚 묶음과 같게).
   - 정답이 여러 개면 `" / "`로, 순서가 있으면 `" → "`로 잇는다. 그림에서 한 줄에 하나씩(순서는 ①②③) 나온다.
   - `q`는 25자 안팎. 정답을 드러내는 말은 쓰지 않는다.
2. 실행: `NODE_PATH=/opt/node22/lib/node_modules node .claude/skills/game-release/scripts/make_answer_sheet.js release/<게임이름>/answers.json release/<게임이름>/screenshots/정답표.png`
3. ⚠ 경고(정답이 너무 긺)가 나오면 `q`를 줄이거나 정답 표기를 확인한다. 만든 그림은 직접 열어 확인하고, 문항 수가 게임과 같은지 본다.

## 3-4단계: 게시판 사진 묶음 (올리는 순서대로 번호 붙이기)

선생님이 사진을 순서대로 올리기 쉽게 **파일 이름 앞에 올리는 번호(1번, 2번 …)를 붙여** `게시판_사진/` 폴더에 모은다. 원본 `screenshots/`는 그대로 둔다.

1. 넣는 사진과 순서 (보통 6장, 많아도 9장):
   1번 시작 화면(이름 쓰기) → 2번 초반 문제 → 3번 초반 오답 힌트 → (보스전이 있으면 보스전 1장) → 결과창 → 교실 TV 안내판 → **정답표는 항상 마지막**
2. 실행 (사진은 release 폴더 기준 경로를 올리는 순서대로):
   `node .claude/skills/game-release/scripts/make_upload_set.js release/<게임이름> screenshots/01_….png screenshots/02_….png screenshots/03_….png screenshots/<결과창>.png screenshots/00_교실TV_게임안내.png screenshots/정답표.png`
3. 결과: `게시판_사진/1번_시작화면_이름쓰기.png`, `2번_초반_문제.png` … `6번_정답표.png` (찍은 순서 번호 `01_`은 떼고 올리는 번호를 붙인다). 이전 묶음은 지우고 새로 만든다.

## 4단계: 보고

대화창에 다음을 짧게 보여 준다.
1. 소개글 전문 (그대로 복사해 게시판에 붙일 수 있게. 글에는 사진 번호를 쓰지 않는다)
2. `게시판_사진/` 파일을 **번호 순서대로** 보낸다 — "1번부터 차례로 맨 위에 올리면 돼요" 한 줄만 덧붙인다
3. 스크린샷 장수·닉네임, 교실 TV 안내판 5문장, 정답표 문항 수 (짧게)
4. 나머지 스크린샷(중반·후반 장면)은 보내지 않고 `screenshots/` 폴더에 있다고만 알린다
5. 확인이 필요한 점 (공유 주소, 발견한 게임 오류 등) — 있을 때만
