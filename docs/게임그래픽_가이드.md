# 게임 그래픽 가이드 (docs/게임그래픽_가이드.md)

> `CLAUDE.md` 2장 "화면과 그래픽"을 **실제로 그리는 방법**이다. 형용사("입체감 있게")가 아니라 레시피와 숫자로 적는다.
> 읽는 때: 장르 추천 전 → 2장 + **`docs/스타일_카탈로그.md`(그림체 고르기)** · 아트 바이블 쓸 때 → 3장 · 만들 때 → 4~8장 · 보고 전 → 9장.
> 실제로 돌아가는 본보기: `docs/그래픽_시안/` (2D 시안, 3D 시안). 여기 나온 함수는 거기서 가져다 쓴다.
> 이전 게임들의 그래픽·화면 틀은 `docs/그래픽_기록.md`에 있다. 카탈로그는 "어떤 그림체로 그리나", 이 문서는 "어떻게 잘 그리나", 기록부는 "무엇이 겹치면 안 되나"다.

## 1. 왜 2000년대처럼 보였나 (저장소 진단, 2026-10)

최근 게임 코드를 열어 보면 원인이 같다. 하나라도 있으면 그 자리에서 고친다.

| 증상 | 실제 사례 | 고치는 법 |
|---|---|---|
| **이모지가 그림 역할** | 최근 게임마다 이모지 100~380개. 분수 급행열차의 화차 과자도 이모지(`drawImage(Emo.get('🍪'))`) | 게임 화면 이모지 0개. 아이콘·소품은 그림체대로 직접 그린다(6장) |
| **시스템 글꼴** | 글꼴 목록 끝이 결국 맑은 고딕 → 학교 PC에서는 모든 제목·숫자가 맑은 고딕 | 무료 게임 글꼴을 파일에 넣는다(7장) |
| **웹 카드 UI** | 흰 둥근 상자 + `box-shadow` 26~65개, 기본 체크박스 | 재질 있는 게임 UI(6장) |
| **단색 면** | 역 건물·화차가 색 하나 + 얇은 선 | 3단 음영 + 질감 + 접지 그림자(4.1, 4.4) |
| **빛 방향 없음** | 물체마다 그라데이션 방향이 제각각 | 아트 바이블에 광원 하나를 정하고 모든 물체에 적용(3장) |
| **외곽선 제각각** | 어떤 것은 굵은 선, 어떤 것은 선 없음 | 앞쪽 물체만 같은 색·같은 굵기 선(4.2) |
| **디테일 밀도 부족** | 넓은 빈 땅·빈 하늘 | 크기가 다른 소품을 3단계로 흩뿌린다(4.3) |
| **장면 + 문제 카드 구도** | 날씨 상자 실험실·천지인 메신저·어린이 방송국 | 문제는 세계 안의 물건으로(6.7) |

반대로 「동그라미 왕국 수비대」는 장르(디펜스)의 기준작 그림이 뚜렷해서 질감 있는 땅, 굵은 외곽선, 소품 밀도를 지켰고 결과도 좋았다(다만 이 게임에도 이모지가 많다. 그 점은 따라 하지 않는다).
**기준작과 레시피를 정해 주면 품질이 올라간다**는 것이 이 문서의 전제다.

**두 번째 진단(2026-10 후반): 이번에는 한 가지 그림체로 굳었다.** 위 처방 뒤에 만든 4게임(빛줄기 서커스, 지구 궤도 관제사, 울림 밴드, 열기구 우편 비행)이 모두 같은 그림이었다. 3단 셀음영 + 진한 외곽선 + 종이 결에, 크림 종이·놋쇠·빨간 도장 UI, 줄에 매달린 종이 문제, 종이 일지 결과를 썼다. 이 문서에 자세한 레시피가 셀음영 하나뿐이었고, UI 재질 목록 첫머리가 나무·놋쇠·종이였기 때문이다.
그래서 그림체는 `docs/스타일_카탈로그.md`(6계열 24종)에서 돌려 가며 고르고, 레시피는 계열마다 둔다(4.10~4.18, 5.1~5.4).

## 2. 장르–그래픽 궁합표

**장르가 그림체를 정하지 않는다.** 디펜스 하나만 해도 굵은 외곽선 카툰, 어두운 픽셀, 로우폴리, 하얀 미니멀 섬, 카드 일러스트, 광택 3D로 갈린다. 이 표는 장르마다 **잘 맞는 시점·연출·UI 배치**와 **그림체가 서로 다른 기준작 여러 개**를 보여 준다. 그림체는 이 중에서, 또는 카탈로그 전체에서 고른다(카탈로그 1장의 순서).
기준작은 **그리는 방식(빛·외곽선·재질·구도·UI 배치)만** 배운다. 캐릭터·로고·UI 모양은 베끼지 않는다(CLAUDE.md 규칙 3). 괄호 안은 카탈로그 스타일 번호다.

### 2-1. 교사가 준 참고 그림에서 뽑은 렌더링 규칙

| 참고 화면 | 배울 것 |
|---|---|
| 벚꽃 기차(3D 기차 게임) | 소실점이 있는 원근, **앞쪽 꽃잎을 크게 흐리게(초점 흐림)**, 나무 기둥으로 화면 틀 만들기, 자갈·전선 같은 잔 디테일 |
| 고블린 디펜스 | 모든 유닛 **같은 굵기 외곽선**, 질감 있는 땅과 흐트러진 길 가장자리, 채도로 적과 땅 구분, 기술 단추에 단축키, 위험할 때 붉은 테두리 |
| 블룬스 TD 6 | 둥글고 말랑한 형태 + 반짝 하이라이트, **흰 글자 + 두꺼운 어두운 테두리**, 초록 입체 단추, 가격이 보이는 상점 칸 |
| 쿠키런 | **배경은 어둡고 탁하게, 전경은 밝고 선명하게**, 젤리의 광택 3종(하이라이트·반사광·반짝이), 돌출된 큰 글자, 줄무늬 게이지 |
| 뉴 슈퍼 마리오 U | 장난감 같은 둥근 형태, 배경은 흐리고 밝게(공기 원근), 부드러운 그림자 |
| 패미컴 마리오 | 납작해도 촌스럽지 않은 이유는 **일관성**: 글자·숫자·UI까지 픽셀, 제한 팔레트, 정수 배율 |
| 오버쿡드 2 | 디오라마 시점, 놀이 구역 밖도 세계, **물체 위 말풍선 아이콘**, 네 귀퉁이 UI(주문표·돈·시간) |

영상 8개에서 뽑은 그림체별 규칙은 카탈로그 4장의 카드마다 있다.

**공통 규칙 6가지:** ① 하나의 렌더링 규칙을 UI까지 ② 전경·배경 분리 ③ 모든 물체 3단 명암(스타일 방식대로) + 그림자 ④ 크기가 다른 디테일 ⑤ 가만히 있어도 움직임 ⑥ UI는 작게, 가장자리에.

### 2-2. 2D와 3D 고르기 (어느 쪽도 기본이 아니다)

| 이럴 때 | 후보 |
|---|---|
| 내려다보는 장난감 세상(경영·건설·요리·디펜스), 입체·방향·부피가 학습 내용(직육면체, 방위, 지형), 원근이 중요한 운전·레이싱 | 3D 툰 |
| 옆에서 보는 액션(러너·플랫포머·포격), 보드·카드·퍼즐, 글을 많이 읽는 단원, 픽셀·수채·종이·민화·잉크 만화처럼 손맛이 중요한 그림체 | 2D |
| 블록으로 쌓고 부수는 것이 학습 내용(부피·쌓기나무·지층), 각진 지형 | 3D 복셀·로우폴리(5.1, 5.2) |
| 둘 다 맞을 때 | 기록부에서 최근 게임들과 다른 쪽, 학생 기기(요청서)에서 잘 도는 쪽 |

- "3D가 더 멋져 보여서"는 이유가 아니다. 2D라서 밋밋해도 되는 것도 아니다. 어느 쪽이든 아트 바이블·채점표·기록부 기준을 똑같이 적용한다.

### 2-3. 같은 장르 안에서 바꾸는 변주 축 (6축)

그림체는 6축의 조합이다: **모양 · 렌더링 · 팔레트 · 빛 · 시점 · UI 재질**(카탈로그 1-1). 같은 복셀도 낮과 네온 밤이면 다른 게임이 된다.
- 스타일 카드에 6축을 한 줄씩 적고, **최근 3개 게임 각각과 4축 이상** 다르게 한다. 기록부 9가지 중 6가지 이상 기준도 그대로다.
- 계열은 카탈로그 5장의 돌려쓰기 규칙을 따른다(최근 3개 게임·같은 과목 최근 3개 게임의 계열 제외).
- 6축 밖에서 더 바꿀 것:
  - **시간·날씨·계절:** 아침 / 한낮 / 노을 역광 / 밤과 조명 / 비·눈·안개 / 봄·여름·가을·겨울
  - **장소의 크기:** 책상 위 미니어처 / 작은 생물 눈높이 / 마을 / 도시 / 하늘·떠 있는 섬 / 바닷속 / 몸속·현미경 / 우주
  - **글꼴:** 7장 표의 분위기별 글꼴
  - **화면 틀:** 6.9의 타이틀·이름 쓰기·스테이지 선택·문제 제시·답 입력·결과

## 3. 아트 바이블 (게임마다 먼저 쓰고, 코드 맨 위 주석에 둔다)

쓰기 전에 `docs/그래픽_기록.md`에서 최근 3개 게임·시안 2개·같은 단원·같은 장르 줄과 계열·6축 표를 본다. **맨 위에 스타일 카드(카탈로그 1-2)를 먼저 쓰고**, 아래 10줄과 화면 틀 5줄을 그 줄들과 **9가지 중 6가지 이상 다르게, 화면 틀은 반드시 다르게** 정한다.
10줄을 채우기 전에는 그림 코드를 쓰지 않는다. 모든 물체와 UI가 이 10줄을 따른다.


## 4. 2D 렌더링 레시피 (캔버스)

### 4.1 셀 음영 3단 — 가장 효과가 큰 한 가지

도형을 빛 쪽으로 밀어 덮으면 반대쪽에 **그늘 초승달**, 반대로 밀어 빼면 빛 쪽에 **빛 초승달**이 남는다. 어떤 도형에도 같은 함수 하나로 입체가 생긴다.

```js
const hex=h=>{ const n=parseInt(h.slice(1),16); return [(n>>16)&255,(n>>8)&255,n&255]; };
const mix=(a,b,t)=>{ const A=hex(a),B=hex(b); return '#'+A.map((v,i)=>Math.round(v+(B[i]-v)*t).toString(16).padStart(2,'0')).join(''); };
const LX=-.62, LY=-.78;                                   // 빛이 오는 방향(왼쪽 위)
const SH=c=>mix(mix(c,'#1c1030',.30),'#5a3d8a',.16);     // 그늘: 어둡게 + 보라 쪽(검정 금지)
const HL=c=>mix(mix(c,'#ffffff',.30),'#ffe7a0',.25);     // 빛: 밝게 + 따뜻하게
function cel(g,shape,base,o={}){ const s=o.s??7,h=o.h??5,ow=o.ow??3; g.save();
  if(ow>0){ g.beginPath(); shape(g); g.lineWidth=ow*2; g.strokeStyle='#3b2516'; g.stroke(); }   // 외곽선(안쪽 절반은 칠로 덮임)
  g.beginPath(); shape(g); g.clip(); g.fillStyle=o.sh||SH(base); g.fill();                        // 전체를 그늘색
  g.save(); g.translate(LX*s,LY*s); g.beginPath(); shape(g); g.restore(); g.fillStyle=base; g.fill(); // 빛 쪽으로 민 바탕 → 그늘 초승달
  if(h>0){ g.beginPath(); shape(g); g.save(); g.translate(-LX*h,-LY*h); shape(g); g.restore();
    g.globalAlpha=.85; g.fillStyle=o.hl||HL(base); g.fill('evenodd'); g.globalAlpha=1; }          // 빛 초승달
  g.restore(); }
```
- 닫힌 도형 하나에만 쓴다. 원 여러 개를 겹친 구름·꽃무더기는 `celL`(화면 밖 캔버스 + `destination-out`)을 쓴다(2D 시안 참고).
- 광택 재질(사탕·젤리·금속)은 바탕 위에 흰 타원 하이라이트 점을 하나 더 얹는다.
- 원통은 **굽은 방향으로** 5단 그라데이션을 준다(누운 보일러는 위 밝음 → 아래 어두움, 선 기둥은 빛 쪽 → 반대쪽) + 빛 쪽에 가는 흰 반짝 줄.

### 4.2 외곽선 규칙
- **앞쪽(조작 대상·캐릭터·아이템)만** 같은 색, 같은 굵기. 굵기는 화면 높이의 0.4% 안팎(720p에서 3px).
- 색은 검정이 아닌 진한 갈색·남색(`#3b2516` 등). 뒤쪽 배경은 선을 빼서 흐려 보이게 한다.

### 4.3 깊이: 층 · 공기 원근 · 시차
| 층 | 처리 | 시차(카메라 1만큼 움직일 때) |
|---|---|---|
| 하늘 | 세로 그라데이션 + 광원 쪽 따뜻한 빛 | 0 |
| 먼 산 | 선 없음, 하늘색에 60~80% 섞기, 그늘 사면 한쪽 | 0.15 |
| 언덕·마을 | 작은 집·나무 점, 안개 덮개 | 0.3 |
| 중경(나무·울타리) | 셀음영, 얇은 선 | 0.55 |
| 무대(건물·땅) | 질감 + 3단 음영 | 0.75~1 |
| 주인공·조작 대상 | 굵은 선, 가장 높은 채도 | 1~1.15 |
| 전경(풀·가지) | **흐리게(4.6)**, 어둡게, 화면 귀퉁이만 | 1.6 |

- **디테일은 크기 3단계**로: 큰 것(나무·건물) / 중간(벤치·화분·가로등) / 작은 것(꽃·자갈·꽃잎). 넓은 빈 면이 없게 한다.
- 화면이 가만히 있어도 카메라를 아주 조금(±9px) 숨쉬게 하면 층마다 다르게 움직여 깊이가 생긴다.

### 4.4 질감
- 값 노이즈(4개 옥타브)를 256px 캔버스에 한 번 만들어 패턴으로 쓴다. 벽·바닥은 `multiply` 15~25%, 풀밭은 `overlay` 30%.
- 나무 판자: 노이즈를 가로로 늘려(`scale(3,.35)`) `multiply` + 판자 이음매 선. 자갈: 작은 타원 2,000개 + 왼쪽 위 작은 하이라이트.

### 4.5 빛
- **광원은 화면 밖**에 둬도 된다(왼쪽 위). 하늘 모서리 따뜻한 원형 그라데이션 + 빛줄기(가는 쐐기 그라데이션 6개, `screen`).
- **빛 번짐(블룸):** 빛나는 것(전등·신호등·계기판 숫자·전구)만 1/4 크기 캔버스에 그리고, 1/8로 줄였다가 화면 크기로 늘려 `lighter`로 더한다. `shadowBlur`·`ctx.filter`를 매 프레임 쓰지 않는다(구형 PC에서 느림).
- 비네트(가장자리 어둡게 35~45%) + 대각선 색보정(빛 쪽 따뜻하게, 반대쪽 보라).
- 시간대 색 덮개: 낮(없음) · 저녁(주황 `multiply` 20%) · 밤(남색 `multiply` 45% + 창문·가로등 빛 번짐). 스테이지가 바뀔 때 시간대를 바꾸면 같은 무대도 새로워 보인다.

### 4.6 초점 흐림(피사계 심도)
- 전경 층을 화면 밖 캔버스에 그린 뒤 **절반씩 3번 줄였다가 다시 키우면** 부드럽게 흐려진다(불러올 때 한 번만). 큰 꽃잎 입자도 크고 반투명하게 그려 흐린 느낌을 낸다.

### 4.7 캐릭터
- 2~2.5등신, **화면 높이 1/5 이상**(조작 캐릭터·안내 캐릭터는 1/3~1/2도 좋다).
- 부위별(머리·몸·팔·꼬리)로 따로 그려 움직인다: 숨쉬기(세로 1.2%), 3~4초마다 깜빡임(0.13초), 꼬리·귀 흔들림, 말할 때 손짓.
- 눈은 큰 검은 타원 + 흰 하이라이트 2개(큰 것 왼쪽 위, 작은 것 오른쪽 아래). 볼 터치 반투명 분홍.
- 표정 4종 이상(보통·기쁨·놀람·아쉬움). 정답·오답 때 몸 전체 반응(늘었다 줄었다 0.15초).

### 4.8 손맛 (숫자로)
| 순간 | 연출 |
|---|---|
| 모든 입력 | 0.1초 안에 소리 + 단추 눌림(3px 아래로) + 작은 입자 |
| 정답 | 반짝이 별 12~20개, 숫자 팝업(외곽선 글자가 위로 떠오르며 커졌다 작아짐), 콤보면 화면 가장자리 빛 |
| 큰 성공 | 히트스톱 60ms → 화면 흔들림 0.25초 → 색종이 |
| 오답 | 대상만 좌우로 3번 흔들림, 화면 전체를 벌주지 않는다. 힌트는 캐릭터가 말한다 |
| 대기 | 가만히 있어도 움직이는 것 5가지 이상(구름·증기·꽃잎·새·깜빡임 등) |

사건을 흐름(입력→준비→행동→변화→결과→정착)으로 보는 법, 중요도별 강도, 반복 플레이 숫자, 중복 깎기는 `docs/연출_점검.md`에 있다. 다 만든 뒤 `juice-critic`에게 점검받는다.

### 4.9 카메라 · 그림자 · 입자 기본
- **카메라:** 게임 세계를 화면보다 넓게 만들고, 따라가기(부드럽게 보간)·흔들기·확대를 쓴다. 고정 화면 게임도 숨쉬기(±9px)는 둔다.
- **그림자:** 모든 물체 발밑에 타원 그림자. 공중에 뜬 물체는 높을수록 그림자를 작고 연하게. 빛 반대쪽으로 조금 밀어 둔다.
- **입자:** 배열을 미리 만들어 다시 쓴다(풀링). 꽃잎·먼지·불꽃·물보라·별·조각. 저사양에서 1/3.
- **의사 3D:** 레이싱 도로는 줄마다 폭을 원근으로 줄여 그리고(가까울수록 넓게), 1인칭 미로는 레이캐스팅을 쓴다. 진짜 입체가 필요하면 5장.

### 4.10 픽셀 (카탈로그 P1~P5)

```js
const PW=320, PH=180, SC=4;                     // 1280×720 = 정수 4배(3배면 426×240). 소수 배율 금지
const px=document.createElement('canvas'); px.width=PW; px.height=PH; const g=px.getContext('2d');
// 매 프레임: g에 그린 뒤 큰 화면에 확대
ctx.imageSmoothingEnabled=false; ctx.drawImage(px,0,0,PW*SC,PH*SC);
// 팔레트(예시 16색, 게임마다 새로 정한다). UI까지 모든 색을 여기서만 고른다
const PAL=['#1a1c2c','#5d275d','#b13e53','#ef7d57','#ffcd75','#a7f070','#38b764','#257179',
           '#29366f','#3b5dc9','#41a6f6','#73eff7','#f4f4f4','#94b0c2','#566c86','#333c57'];
// 스프라이트는 글자 배열(16진수 한 글자 = 팔레트 번호, '.' = 빈칸). 불러올 때 한 번 캔버스로 굽는다
function sprite(g,rows,x,y){ rows.forEach((r,j)=>[...r].forEach((ch,i)=>{
  if(ch!=='.'){ g.fillStyle=PAL[parseInt(ch,16)]; g.fillRect(x+i,y+j,1,1); } })); }
// 그라데이션 대신 2×2 점 섞기(디더링). t(i,j)는 0~1(c2 비율). 불러올 때 한 번 굽는다
const BAYER=[0,2,3,1];
function dither(g,x,y,w,h,c1,c2,t){ for(let j=0;j<h;j++) for(let i=0;i<w;i++){
  g.fillStyle=(BAYER[(i&1)+((j&1)<<1)]/4<t(i,j))?c2:c1; g.fillRect(x+i,y+j,1,1); } }
```
- 팔레트는 16~32색. 타일 16px, 캐릭터 16×24px 안팎.
- 외곽선은 1px이고, 검정 대신 닿는 색보다 두 단계 어두운 색을 쓴다.
- 움직이는 좌표는 `Math.round`로 정수 픽셀에 맞춘다. 반 픽셀 떨림이 없어야 한다.
- **글자:** 작은 캔버스에 쓰면 흐려진다. 큰 화면에 Galmuri11을 11px의 정수 배(44px)로 쓰고, 좌표를 4px 격자에 맞춘다.
- **빛과 그림자도 계단으로:** 둥근 빛은 3~4단 동심원, 그림자는 팔레트의 어두운 색 한 단계.
- 대기 동작은 2~4프레임 반복(0.15~0.25초 간격). 부드러운 보간보다 딱딱 끊기는 맛이 픽셀답다.
- 저사양: 원래 가볍다. 빛·입자만 줄인다.

### 4.11 HD-2D (P5)
- 두 층으로 나눈다.
  - **픽셀 층**(캐릭터·물체·타일): 4.10 방식으로 4배 확대
  - **빛 층**(원래 해상도): 깊이에 따라 색이 바뀌는 배경 그라데이션, 빛줄기(4.5), 블룸(4.5), 미리 흐린 먼 배경(4.6), 떠다니는 작은 입자
- 그리는 순서: 빛 층 배경 → 흐린 먼 픽셀 층 → 픽셀 무대·캐릭터 → 빛줄기·입자(`screen`·`lighter`) → 블룸 → 픽셀 UI.
- 물속이면 위에서 내려오는 빛 무늬(코스틱)를 넣는다. 흰 곡선 여러 개를 `lighter` 10%로 천천히 흔든다.
- 픽셀 층에 매끈한 그라데이션을 칠하지 않는다. 매끈한 것은 모두 빛 층에 둔다.

### 4.12 밤과 빛 구멍 (P3, 모든 밤 장면)

```js
// 어둠 캔버스는 화면 1/4 크기(320×180): 가볍고, 늘려 그리면 가장자리가 저절로 부드럽다
const dark=document.createElement('canvas'); dark.width=320; dark.height=180; const dk=dark.getContext('2d');
function drawNight(lights){                     // lights: [{x,y,r}] 어둠 캔버스 좌표
  dk.globalCompositeOperation='source-over'; dk.fillStyle='rgba(20,18,60,.82)'; dk.fillRect(0,0,320,180);
  dk.globalCompositeOperation='destination-out';           // 빛 자리를 뚫는다
  for(const L of lights){ const r=dk.createRadialGradient(L.x,L.y,0,L.x,L.y,L.r);
    r.addColorStop(0,'rgba(0,0,0,1)'); r.addColorStop(1,'rgba(0,0,0,0)'); dk.fillStyle=r; dk.fillRect(L.x-L.r,L.y-L.r,L.r*2,L.r*2); }
  ctx.drawImage(dark,0,0,1280,720);                          // 어둠 덮기
  ctx.globalCompositeOperation='lighter';                    // 빛 색 더하기(30~45%)
  for(const L of lights){ const x=L.x*4,y=L.y*4,R=L.r*4, r=ctx.createRadialGradient(x,y,0,x,y,R);
    r.addColorStop(0,'rgba(255,160,70,.4)'); r.addColorStop(1,'rgba(255,160,70,0)'); ctx.fillStyle=r; ctx.fillRect(x-R,y-R,R*2,R*2); }
  ctx.globalCompositeOperation='source-over'; }
```
- 불꽃 빛은 반지름을 `r*(1+0.04*Math.sin(t*13)+0.03*Math.sin(t*7.7))`로 흔든다.
- 빛 원 안의 물체에는 빛 쪽 가장자리에 따뜻한 테두리 빛 1~2px을 넣는다.
- 픽셀 게임은 그라데이션 대신 3~4단 동심원으로 뚫는다.
- 문제 글 판은 어둠을 덮은 **뒤에** 그린다. 어둠이 글을 덮으면 안 된다.
- 저사양: 빛은 6개까지만.

### 4.13 아이소메트릭 타일 (I1)

```js
const TW=64, TH=32;                               // 마름모 2:1
const iso=(i,j,z=0)=>[OX+(i-j)*TW/2, OY+(i+j)*TH/2-z];   // 칸 (i,j)의 윗꼭짓점 화면 좌표, z는 높이
const pick=(x,y)=>{ const a=(x-OX)/(TW/2), b=(y-OY)/(TH/2);  // 화면 → 칸 (땅 높이 기준)
  return [Math.floor((a+b)/2), Math.floor((b-a)/2)]; };
```
- 칸마다 세 면을 칠한다: 윗면 = 바탕, 왼쪽 면 = 그늘, 오른쪽 면 = 더 진한 그늘(빛이 왼쪽 위일 때).
- 그리는 순서는 `i+j`가 작은 칸부터(뒤 → 앞)다. 같은 줄 안에서는 낮은 것부터 그린다.
- `pick`은 땅 높이 기준이다. 높은 칸을 누르게 하려면 앞쪽 칸부터 윗면 마름모 안에 점이 있는지 차례로 확인한다.
- 칸이 채워질 때(꽃·건물) 아래에서 솟으며 튕기고(0.25초) 흙먼지가 인다. 성장이 보이는 세계(카탈로그 7장)와 잘 맞는다.

## 5. 3D 레시피 (three.js를 파일 안에 넣기)

**언제:** 경영·건설·요리·디펜스·레이싱처럼 "장난감 세상을 내려다보는" 장르, 또는 입체가 학습 내용인 단원(직육면체·방향·지형). 교실 PC가 매우 낡았다고 요청서에 적혀 있으면 2D로 간다.

**만드는 법** — `docs/그래픽_시안/src/build_3d.sh` 한 줄로 한다(저장소 밖 작업 폴더에서 three.js를 묶는다. 저장소에 `node_modules`·`package.json`을 만들지 않는다).
```bash
bash docs/그래픽_시안/src/build_3d.sh <게임코드.js> <페이지.html> <결과.html>
```
- **three.js r162**를 쓴다. WebGL1 컴퓨터까지 되는 마지막 판이다(r163부터 WebGL1 지원 중단).
- 게임 코드가 쓰는 `THREE.이름`만 골라 묶고 압축해 첫 `<script>`에 넣는다(전역 `THREE`). 맨 위에 `three.js r162 — MIT License` 주석을 남긴다.
- **게임 코드는 압축하지 않고** 두 번째 `<script>`에 그대로 넣는다. 다음 세션이 HTML을 직접 고칠 수 있어야 한다(참고 문서 1장). 게임 코드에는 `import`를 쓰지 않는다.
- 묶을 때 `--charset=utf8`을 쓴다. 빼면 한글이 `\uXXXX`로 바뀐다.
- 파일 크기는 three.js 묶음 약 500KB만큼 늘어난다.

**보기 좋게 만드는 6가지** (`docs/그래픽_시안/src/분수철도섬_3D_main.js`)
1. **툰 셰이딩:** `MeshToonMaterial` + 3단 `gradientMap`(값 120·196·255, RGBA DataTexture, Nearest).
2. **외곽선:** 같은 도형을 조금 크게 만든 뒷면 전용 검은 껍데기(`side: BackSide`). 도형은 회전·이동을 메시에 주고 지오메트리는 가운데에 둔다.
3. **빛:** 반구광(하늘 `#eef8ff` / 땅 `#f5cfa8`) + 왼쪽 위 따뜻한 해(그림자 PCFSoft 2048).
4. **장난감 느낌:** 둥근 기본 도형 조립, 꽃·자갈은 `InstancedMesh`로 수백 개, 바다는 단색 + 물결 무늬 텍스처 흐르기 + 섬 둘레 거품 고리.
5. **미니어처 초점 흐림:** 렌더 타깃에 그린 뒤 화면 위·아래로 갈수록 흐려지는 셰이더(14번 샘플) + 비네트 + 색보정. 출력 끝에 `#include <colorspace_fragment>`.
6. **UI는 2D 캔버스를 위에 겹친다.** 3D 위치를 `vector.project(camera)`로 화면 좌표로 바꿔 말풍선·이름표를 그린다.

**저사양:** 픽셀 배율 0.75, 그림자·후처리 끔, 꽃잎·꽃 개수 1/4.
**WebGL이 없을 때:** 규칙 5 때문에 안내 문구만으로는 안 된다. 같은 규칙·같은 문제로 끝까지 할 수 있는 **간단한 2D 대체 화면**(위에서 본 지도 그림 + 같은 UI)을 함께 만든다. 렌더링과 게임 규칙 코드를 나눠 두면 쉽다.

**미리 렌더링해 굽기(3D처럼 보이는 2D):** 3D 모형을 제작 단계에서 Playwright로 여러 각도·동작별로 찍어 스프라이트 그림(WebP)으로 구워 base64로 넣는다. 실행할 때는 그림만 그리는 2D라 구형 PC에서도 가볍고, 그대로 WebGL 없는 PC의 대체 화면으로도 쓸 수 있다. 직접 만든 모형을 찍은 것이므로 규칙 4의 "코드로 그려 이미지로 구워 넣기"에 해당한다. 그림 하나는 256px 안팎, 전체 2MB 이하로 한다.

### 5.1 로우폴리 (카탈로그 B3, B4)

```js
// 면이 각지게: 꼭짓점을 조금씩 흔든 뒤 면마다 한 색(flatShading). 같은 자리 꼭짓점은 같이 움직여 틈이 생기지 않는다
function lowpoly(geo,amp){ geo=geo.index?geo.toNonIndexed():geo; const p=geo.attributes.position, seen=new Map();

    const d=seen.get(id); p.setXYZ(k,p.getX(k)+d[0],p.getY(k)+d[1],p.getZ(k)+d[2]); }
  geo.computeVertexNormals(); return geo; }
```

- 빛: 낮은 각도의 해 하나(노을) + 약한 반구광 → 긴 그림자. `Fog`로 먼 곳을 하늘색에 섞는다.

### 5.2 복셀 (B1, B2)

```js
const mesh=new THREE.InstancedMesh(new THREE.BoxGeometry(1,1,1),new THREE.MeshLambertMaterial(),vox.size);
```

| 그래픽·공예 | 청사진 선, 칠판·분필, 한지 + 먹 테 + 매듭, 유리·네온, 돌·석판 |

- 나무·놋쇠·법랑·종이도 위 재질 가운데 하나일 뿐, 기본값이 아니다.
- **크림 종이 + 놋쇠 테 + 빨간 도장·밀랍** 조합은 쓰지 않는다. 4게임 연속으로 썼다(기록부 "되풀이된 틀").
- 흰 둥근 상자 + `box-shadow`는 쓰지 않는다.

### 6.2 글자
- 제목·숫자는 게임 글꼴(7장) + **두꺼운 어두운 외곽선(글자 크기의 15~20%)** + 아래 그림자. 큰 연출 글자는 돌출(같은 글자를 아래로 4~8번 진한 색으로 겹친 뒤 위에 그림).
- 본문(문제 글)은 25px 이상, 줄 간격 1.4. UI 재질의 밝은 판에 진한 글자(또는 어두운 판에 밝은 글자)로 대비를 강하게. 핵심 숫자는 강조색 + 형광펜 띠, 빈칸은 점선 상자로 그린다.

### 6.3 단추·게이지·패널
- 단추: 외곽선 → 바탕(셀음영) → 안쪽 오목 원 → 아이콘. 누르면 3px 내려가고 그림자가 줄어든다.
- 게이지: 둥근 홈 + 채움색(초록→노랑→빨강) + 사선 줄무늬가 흐름. 끝에 아이콘(하트·모래시계).
- 숫자 표시: 어두운 유리창 + 주황 숫자 + 빛 번짐(블룸) + 위쪽 반사광.

### 6.4 아이콘은 직접 그린다
음악(음표 두 개), 소리(스피커 + 물결 2줄), 멈춤(둥근 막대 2개), 동전(셀음영 원 + 안쪽 원 + 글자), 전구, 과자, 사과, 우유 등. 2D 시안·3D 시안의 `brassBtn`, `coinIcon`, `icCookie`, `icApple`, `icMilk`를 본보기로 쓴다.

### 6.5 배치
- HUD는 **가장자리에 작게** 두고, 화면 가운데 60%는 게임 세계가 차지한다.
- 배치 모양은 스타일마다 다르게 고른다. 최근 3개 게임과 같은 배치는 피한다.
  - 네 귀퉁이(디오라마·디펜스)
  - 위 한 줄 정보 띠 + 아래 한 줄 메뉴 띠(단면도 경영)
  - 아래 큰 대화창(이야기형)
  - 세계 속 물건이 곧 계기(기구의 온도계, 배의 키)
  - 손에 든 카드 부채(카드형)
- 진행 표시는 장르 물건으로(기차면 작은 선로 위 역 점, 요리면 주문표).
- 체크박스·입력칸·설정은 톱니바퀴 창 안으로. 닉네임은 시작 단추를 누른 뒤 승차권·명찰에 쓰는 장면으로.

### 6.6 글이 많은 화면과 입력칸
- 긴 지문·오답 노트·결과처럼 글이 많은 화면은 DOM으로 만든다(줄바꿈·넘침 확인이 쉽다). 대신 **그 게임의 UI 재질**(픽셀 창·만화 칸·청사진·칠판·한지 등), 게임 글꼴, 직접 그린 장식으로 꾸민다. 종이 일지로 굳지 않게 한다.
- 이름 입력은 한글 입력기 때문에 실제 `<input>`을 쓴다. 테두리·배경을 없애고 게임 글꼴을 입혀 승차권·명찰 그림 위에 겹친다.

### 6.7 문제를 세계 안에 놓기
운송장·주문표·팻말·상대가 내민 카드·물체 위 말풍선·만화 칸·청사진 빈칸처럼 **그 세계에 있을 법한 물건**에 문제를 쓴다. 줄에 매달린 종이(신청서·큐 시트·편지 꼬리표)는 3게임 연속으로 써서 되풀이된 틀이 되었다. 긴 지문은 그 물건을 눌러 크게 펼친다(두루마리·책). 문제 패널이 화면 절반을 늘 차지하지 않게 한다.

### 6.8 화면 전환
흰 화면 깜빡임 대신 장르 연출: 원형으로 닫히기(아이리스), 기차 지나가며 닦기, 종이 넘기기, 구름이 덮었다 걷히기. 0.4~0.6초.

### 6.9 화면 틀 고르기 (한 가지 모양으로 굳지 않게)

규칙이 한 가지 모양을 정해 주면 매번 그 모양으로 굳는다. 실제로 최근 3개 게임의 첫 화면이 같은 틀이었다(기록부 "타이틀 C"). 아래에서 **이 세계에 맞는 것**을 고르고, 기록부의 최근 게임과 겹치지 않게 한다. 목록에 없는 새 형태도 좋다. ★는 영상 8개에서 새로 가져온 틀이다.

**타이틀** (게임 장면이 움직이는 상태에서)
- 카메라가 세계를 천천히 날아가다 세계 속 간판·건물에 로고가 켜진다
- 캐릭터가 로고 글자를 하나씩 들고 와 세운다
- 책·지도·상자·두루마리가 펼쳐지며 로고가 나온다
- 무대 커튼이 열린다(공연·방송·대결)
- 게임이 바로 돌아가고, 한쪽에 작은 로고와 "아무 곳이나 눌러 시작"
- 픽셀 아케이드처럼 깜빡이는 "누르면 시작"
- 3D 디오라마가 천천히 돌고 그 위에 로고가 떠 있다
- 신문 1면·영화 포스터·우표처럼 한 장의 그림
- ★ 풍경 그림 위에 영화 첫 장면처럼 큰 장면 제목 카드가 떠오름(Life Below)
- ★ 구름이 걷히며 세계가 드러나고 로고가 그 땅에 새겨짐(Dragon Shelter)
- ★ 블록이 하나씩 떨어져 쌓이며 로고가 됨(복셀)
- ★ 옛 필름 카운트다운 원(3·2·1) 뒤에 제목 자막 카드(고무호스 만화)
- (되풀이됨) 한쪽에 줄로 매단 "눌러서 ○○!" 판 + 아무 곳이나 눌러 시작 — 빛줄기 서커스, 열기구 우편 비행

**이름 쓰기** (명찰·승차권·선수증 같은 카드형은 최근에 여러 번 썼다)
- 캐릭터가 대화로 이름을 묻는다 · 칠판에 분필로 · 모래에 손가락으로 · 편지 봉투 겉면에 · 우주선 계기판에 · 출석부에 서명
- ★ 큰 초상 대화창에서 캐릭터가 묻고 대화창에 바로 입력(Grave Seasons) · ★ 픽셀 창 입력칸 · ★ 블록을 쌓아 만든 이름판

**스테이지 선택** (카드 3~5장 가로 배열은 쓰지 않는다)
- 보드게임판 길 위의 칸 · 섬이나 행성 사이를 배·우주선으로 이동 · 탑·건물 층(엘리베이터 단추) · 책 목차·책갈피 · 달력 날짜 · 마을 건물의 문 · 진열장
- ★ 구름 걷힘 지도(되살린 곳만 맑고 색이 있다, Dragon Shelter) · ★ 단면도 건물의 방이 하나씩 열림(카이로소프트) · ★ 떠 있는 섬들을 도는 카메라(Loftia) · ★ 도감 페이지
- (되풀이됨) 종이 지도 위 핀 + 탈것이 점선 따라 이동 · 아래→위로 쌓인 세로 단계

**문제 제시**
- 캐릭터 말풍선 · 세계 속 물건(운송장·주문표·팻말·신문) · 상대가 내민 카드 · 전광판·칠판 · 적이 든 팻말 · 라디오·방송(소리 + 자막) · 퍼즐 판 자체가 문제 · 물체 위 아이콘 말풍선
- ★ 큰 초상 대화창의 대사(Grave Seasons) · ★ 만화 한 컷(문제가 칸 안 장면, 포션 타이쿤) · ★ 손에 든 카드 부채(나인 킹즈) · ★ 단면도 사람들 머리 위 아이콘(카이로소프트) · ★ 청사진 위 치수 빈칸
- (되풀이됨) 줄·집게에 매달린 종이(신청서·큐 시트·편지) · 화면 한쪽에 선 2~2.5등신 동물·로봇 안내역이 힌트·해설을 말함

**답 입력** (게임 조작이 곧 답이 되게)
- 끌어다 놓기·나눠 싣기 · 선 그어 자르기·나누기 · 붓기·채우기(양) · 쌓기 · 조준해 쏘기·던지기 · 길 그리기·잇기 · 저울에 올리기 · 카드 내기 · 글자·낱말 조각 맞추기 · 타이밍 맞춰 누르기 · 돌려 맞추기 · 갈림길·문 고르기 · 숫자 위아래 단추(최근 두 게임이 썼다)
- ★ 블록 쌓기·부수기(복셀) · ★ 칸에 심기·짓기(아이소) · ★ 어둠 속을 등불로 비춰 찾기(밤과 빛 구멍)

**결과** (오답 노트는 그다음 장에, 그 게임 UI 재질로)
- ★ 시상대: 지난 내 기록 3개와 이번 기록이 단상에 서고, 등급 배지에 날개가 돋는다(쿠키런 랭킹 화면)
- ★ 도감 등록: 이번 판에 모은 것이 카드로 날아와 칸에 꽂힌다
- ★ 되살린 세계 전경: 카메라가 물러나며 오늘 바꾼 세계를 보여 준다(카탈로그 7장)
- 만화 마지막 장 · 필름 엔딩 자막 원 · 픽셀 창 점수판
- (되풀이됨) 종이 일지·기록지·공연 프로그램 책 — 빛줄기 서커스, 지구 궤도 관제사, 열기구 우편 비행

  - 본문 글꼴에 필요한 기호가 없으면 Do Hyeon을 **기호용으로 작게** 넣고 글꼴 목록 두 번째에 둔다: CSS `font-family:"Jua","DoHyeon",sans-serif`, 캔버스 `ctx.font='25px Jua, DoHyeon'`, 넣을 때 `__DOHYEON__=docs/fonts/DoHyeon-Regular.ttf@기호.txt`.
  - 가운뎃점·별·동그라미는 작은 원·별을 직접 그려도 된다. `½` 같은 분수 기호는 쓰지 말고 숫자 + 가로선을 그린다.
- 글꼴은 `document.fonts.load()`가 끝난 뒤 그리기 시작한다. 글꼴 이름 옆에 대체 글꼴(`sans-serif`)을 둔다.

## 8. 저사양 · 성능

- 움직이지 않는 층은 불러올 때 화면 밖 캔버스에 한 번 그린다(캐시). 한 프레임 4ms 목표(참고 문서 1장).
- **저사양 모드에서 바꾸는 것:** 카메라 숨쉬기 끄기 → 움직이지 않는 층을 **한 장으로 합쳐** 한 번만 그리기, 블룸·빛줄기·비네트 끄기, 입자 1/3, 해상도 배율 1.
  - 2D 시안에서 이렇게 하면 같은 컴퓨터 기준 프레임 시간이 약 1/3이 됐다. 구도와 그림체는 그대로다.
- `shadowBlur`, `ctx.filter`, `getImageData`를 매 프레임 쓰지 않는다.
- 검증: Playwright에서 CPU를 4배 느리게(`Emulation.setCPUThrottlingRate`) 해 저사양 모드가 끊기지 않는지 본다. 헤드리스 브라우저는 그래픽 카드를 쓰지 않아 3D가 실제보다 훨씬 느리게 나오니, 3D 속도는 교사에게 학교 PC 확인을 부탁한다.

## 9. 그래픽 채점표 (새 게임·그래픽 다시 입히기 · `art-critic` 서브에이전트가 채점)

각 항목 1~5점. **모든 항목 4점 이상**이어야 보고한다. 제작자가 아니라 `.claude/agents/art-critic.md`가 화면과 코드만 보고 채점한다.
- 키 아트 단계에서는 1~7번과 9번만 채점한다(타이틀·움직임·보상은 아직 없다). 완성 단계는 11개 모두.
- 4점 미만 항목을 가장 큰 것부터 고친 뒤 다시 받는다. 고치지 않은 같은 화면으로 다시 받지 않는다. **3번 받아도 미달이면** 점수와 남은 문제를 보고하고 교사가 정한다.

**넘길 것** (모두 1280×720으로 찍는다)
- 스크린샷: 타이틀 · 플레이 대기 화면 0초·0.5초·1초 3장(움직임 판정용) · 정답 순간 · 오답 + 힌트 · 결과(오답 노트) · 저사양 모드(`?low=1` 등) 1장
- 게임 HTML 경로(비평가가 이모지·글꼴·웹 카드 흔적을 코드에서 찾는다)
- **스타일 카드**(카탈로그 1-2) + 아트 바이블 10줄 + 화면 틀 5줄, 장르와 기준작 이름
- 그래픽 기록부 경로와 최근 3개 게임의 첫 화면·플레이 화면 스크린샷(`release/<게임>/screenshots/`에 있으면 그것, 없으면 찍어서)

**차별성 관문:** 비평가가 기록부 9가지로 최근 3개 게임·시안 2개·같은 단원·같은 장르 게임과 비교한다. **어느 하나와라도 다른 것이 6가지 미만이거나, 화면 틀(8·9번)이 겹치거나, "되풀이된 틀"을 쓰면** 점수와 상관없이 "다시"다.
**스타일 관문:** 스타일 카드를 기록부 "계열·6축 표"와 비교한다. 하나라도 어기면 "다시"다.
- 계열 돌려쓰기(카탈로그 5-1): 최근 3개 게임과 같은 과목 최근 3개 게임의 계열을 쓰지 않았는가
- 최근 3개 게임 각각과 6축 중 4축 이상 다른가
- UI 재질이 직전 2개 게임과 다른가
- 화면이 스타일 카드의 렌더링대로 보이는가(예: 카드는 "픽셀"인데 셀음영 외곽선 그림이면 어긋남)

| # | 항목 | 5점 | 1점 |
|---|---|---|---|
| 1 | 장르 적합 | 기준작 옆에 둬도 같은 장르 게임으로 보인다 | 장르와 상관없는 학습지 화면 |
| 2 | 아트 바이블 일관성 | 빛 방향·외곽선·음영·팔레트가 UI까지 예외 없음 | 물체마다 제각각, 이모지 섞임 |
| 3 | 입체감 | 모든 주요 물체 3단 명암 + 접지 그림자. 명암은 스타일 방식대로(셀음영 · 픽셀 팔레트 단계 · 로우폴리 면 · 망점·빗금 · 민화 무늬선) | 단색 납작 |
| 4 | 깊이 | 5겹 이상 + 공기 원근 + 시차(또는 3D) + 초점 흐림 | 배경 한 장 |
| 5 | 전경·배경 분리 | 조작 대상이 0.5초 안에 눈에 띔 | 배경과 섞여 안 보임 |
| 6 | 디테일 밀도 | 크기 3단계 소품, 넓은 빈 면 없음 | 넓은 단색 면 |
| 7 | 캐릭터 | 크고, 표정·대기 동작·반응 동작 | 작고 움직이지 않음 |
| 8 | 움직임·손맛 | 대기 화면 3장 사이에 5가지 이상 움직임, 정답·오답 반응 연출 | 3장이 똑같음 |
| 9 | 게임 UI | 재질·외곽선 글자·직접 그린 아이콘, 가장자리 배치 | 웹 카드·기본 체크박스 |
| 10 | 첫인상 | 움직이는 타이틀 장면 + 30초 안에 "우와" 장면 | 웹 양식 같은 첫 화면 |
| 11 | 아이 눈높이 | 카탈로그 9장 5가지(1/4로 줄여도 읽히는 실루엣 · 초점에 가장 높은 채도 · 과장된 표정 · 보상 공개 장면 · 모으기)를 모두 갖춤. 갖춘 수가 곧 점수(0~1개는 1점) | 하나도 없음 |

**바로 다시 만들 신호** (하나라도 보이면 점수와 상관없이 고친다)
기록부의 "되풀이된 틀"(크림 종이 + 놋쇠 + 빨간 도장 UI, 줄에 매달린 종이 문제, 종이 일지 결과 포함) · 스타일 카드와 다른 렌더링(모든 스타일에 셀음영 외곽선을 덮어씌움) · 게임 화면의 이모지 · 맑은 고딕 같은 시스템 글꼴 제목·숫자 · 흰 둥근 카드 + 그림자만 있는 UI · 기본 모양 그대로의 체크박스·입력칸 · 화면 절반을 차지하는 문제 패널 · 그림자 없는 물체 · 가만히 두면 아무것도 안 움직이는 화면.

**비교 방법:** 새 게임 스크린샷(첫 화면·플레이·정답 순간)과 스타일 카드의 기준작(카탈로그 4장 카드)·2-1의 기준작 설명을 나란히 놓고, "기준작 옆에 두면 무엇이 초라한가"를 화면 위치까지 적어 큰 것부터 고친다. 최근 3개 게임과는 구도·UI 배치·색감이 겹치는지 본다.
