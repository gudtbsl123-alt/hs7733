# 게임 제작 참고 (docs/게임제작_참고.md)

> `CLAUDE.md`의 보충 자료다. **설계를 정해 주는 문서가 아니라** 이 저장소에서 쌓인 기술 경험과 절차를 모아 둔 것이다.
> 여기 나온 방법보다 더 나은 방법이 있으면 그걸 쓴다.

---

## 1. 검증된 기술 선택지 (골라 쓰기)

- **고정 무대 확대:** 1280×720 무대를 `transform: scale`로 창에 맞춘다.
  - 캔버스는 `devicePixelRatio`를 반영하되 최대 2배로 한다.
  - 캔버스 게임에 잘 맞는다. 쓴 게임: 쿠키 러너, 말이 되는 섬, 동그라미 왕국.
- **SVG·DOM 중심:** 지도·보드·카드 게임에 잘 맞는다. 쓴 게임: 기후 벨트 지구본.
  - 남은 세로 공간을 JS로 재서 크기를 맞춘다.
- **아이소메트릭 입체:** 직육면체·원기둥·구 같은 기본 도형 그리기 함수를 만들어 조립한다. 쓴 게임: 코스터 타이쿤.
  - 배경을 정적 층(미리 그려 캐시)과 움직이는 층(물결·반짝임)으로 나누면 빠르다.
- **정적 배경 캐시:** 무거운 배경은 화면 밖 캔버스에 한 번 그려 재사용한다. 목표는 한 프레임 4ms 이하.
- **저장:** `localStorage`는 try/catch로 감싸 쓰고, 게임마다 저장 키를 다르게 한다.
- **터치 감지:** `window.matchMedia('(pointer:coarse)')`와 첫 터치로 감지해 터치 안내·버튼을 보여 주고, 키보드를 쓰면 되돌린다.
- **터치·화면 비율 기본 묶음** (모든 게임에 처음부터 넣는다. 실제 코드: 울림 밴드 `fit()`·`#rotateHint`·`ampShownAt`):
  - 무대를 `min(창너비/1280, 창높이/720)`으로 맞추고 가운데에 둔다. `resize`·`orientationchange` 때 다시 맞춘다.
  - 세로로 든 터치 기기(`(pointer:coarse)` 또는 폭 700 미만)에 '가로로 돌리기' 쪽지 + '이대로 할래요' 단추.
  - 화면을 덮는 DOM 화면은 `pointer-events:none`, 그 안의 단추·입력칸만 `auto`.
  - 새로 나타난 보기는 0.35초 동안 클릭을 받지 않는다(터치 뒤 따라오는 클릭 막기).
  - `document.addEventListener('contextmenu', e=>e.preventDefault())`, `body{ -webkit-touch-callout:none; user-select:none; touch-action:manipulation }`, 캔버스는 `touch-action:none`.
  - 마우스 올림 효과는 `@media (hover:hover)` 안에만.
- **키 누르고 있기:** 브라우저 자동 반복(`e.repeat`) 대신 직접 반복 타이머를 쓴다.
- **자동 생성 콘텐츠:** 무작위 배치나 퍼즐은 "항상 풀 수 있는가"를 코드로 검사한다(예: BFS 풀이기). 게임 중 상태가 바뀌어 막힐 수 있으면 다시 검사하고, 막히면 다시 배치한다.
- **큰 게임 작업 방식:** scratchpad에 `src/` 조각과 합치는 스크립트를 두고 HTML 하나로 합친다.
  - 저장소에는 합쳐진 HTML만 올라가므로 다음 세션은 HTML을 직접 고친다.
  - 섹션 주석을 잘 달고 압축하지 않는다. 3D 게임의 three.js 묶음만 압축하고, 게임 코드는 그대로 둔다(그래픽 가이드 5장).
- **배경음악 넣기:** mp3를 base64로 바꿔 파일 맨 끝 `<script type="text/plain" id="bgm1">`에 둔다. 처음 쓸 때 `data:` URL로 읽는다.

## 2. 실제로 겪은 버그 (다시 만들지 말 것)

| 증상 | 원인 → 해결 |
|---|---|
| 문제를 푼 뒤 게임이 멈춤 (테트리스 퀴즈) | 모달을 닫을 때 루프·입력 상태를 안 되살림 → 닫는 모든 경로에서 재개 확인 |
| 스페이스를 누르고 있으면 게임이 안 끝남 | 게임 오버 판정 누락 → 경계를 보이게 그리고 넘으면 종료 |
| 요소가 영영 안 보임 | 숨긴 요소에 `style.display=''` → 클래스 토글 또는 값 명시 |
| 스크립트 전체 정지 | `const` 선언 전 사용(TDZ) → 전역은 위에 선언 |
| 픽셀 글꼴 글자가 뿌옇게 번짐 (골목 민원 해결단) | Galmuri11을 11의 배수(22·33px)로 씀 → 이 글꼴은 12px 격자라 12의 배수(24·36·48px)에서만 또렷하다. 크기를 바꾸면 줄 간격·칸 높이·자료 표 칸 너비도 함께 다시 맞추고 배치 검사를 다시 돌린다 |
| '통계'가 '동계'로 읽힘 (골목 민원 해결단) | Galmuri11 Bold의 통·퉁·툼·특·틀은 ㅌ의 윗획과 가운데 획이 붙어 ㄷ처럼 보인다 → `docs/fonts/patch_galmuri_t.py`로 ㅌ을 다섯 줄로 다시 그린 사본을 만들어 넣는다(OFL, 예약 이름 없음). 픽셀 글꼴을 쓸 때는 게임에 나오는 글자를 크게 찍어 비슷한 글자(ㄷ/ㅌ, ㅁ/ㅂ)를 눈으로 확인한다 |
| 첫 효과음이 안 남 | `AudioContext.resume()` 전에 재생 → 첫 입력에서 깨운 뒤 재생 |
| 캔버스가 처음에 빈 화면 | 배율 변수 초기값 때문에 초기화 건너뜀 → 0으로 시작 |
| 통계가 두 배 | 기록을 두 곳에서 push → 한 곳에서만 |
| 긴 문제에서 패널이 넘침 | 고정 높이 → 모든 문항을 띄워 넘침을 측정, 긴 글은 "크게 보기" |
| 시작하자마자 부딪힘, 아이템이 장애물 옆 | 배치 검증 없음 → 안전 출발 구간, 안전 위치에만 아이템 |
| 자동 생성 퍼즐이 중간에 막힘 | 처음 배치만 검사 → 상태가 바뀌면 다시 검사 |
| ❤ 가 검은 글자로 보임 | 이모지는 OS마다 다르게 보인다 → 게임 화면에서는 하트를 직접 그린다(허브 아이콘은 `❤️`처럼 변형 선택자) |
| "먹깨비이(가)" | 고정 조사 → 받침으로 조사 고르는 함수 |
| 2번 문제부터 상자를 집고 옮길 수 없음 (블록 항구 크레인 키 아트) | 새 상자가 하늘에서 떨어지는 중에 집어서, 떨어지기 물리가 크레인에 든 상자를 계속 끌어내림 → 떨어지는 중이면 땅에 닿을 때까지 기다렸다 집고, 낙하 처리는 부두 위 상자에만 적용. 배가 다 들어오기 전에 내리지 않게도 막는다. 키 아트도 다음 문제까지 이어서 직접 눌러 본다 |
| 겹치는 표시·두 번 뜨는 알림 | 상태 조합 확인 안 함 → 화면 상태별 스크린샷 확인 |
| **(터치)** 타이틀의 북·손잡이를 눌러도 시작이 안 됨 (울림 밴드) | 화면을 덮은 DOM 화면(`.screen`)이 캔버스 누르기를 가로챔 → 덮개는 `pointer-events:none`, 단추·입력칸만 `auto`. `game-verify`가 "시작 조작이 안 됨"으로 잡는다 |
| **(터치)** 안내를 손가락으로 넘겼더니 1번 답이 저절로 골라짐 (울림 밴드) | 터치 뒤 브라우저가 따라 보내는 클릭이 방금 나타난 보기 단추를 누름 → 새 보기는 나타난 뒤 0.35초 동안 입력을 받지 않는다(봇은 함수를 직접 불러 영향 없음) |
| **(터치)** 이름을 쓴 뒤 시작을 눌러도 키보드만 닫힘 | 이름 칸에 초점이 있으면 첫 탭을 무시함 → 초점을 풀고 바로 시작 |
| **(터치)** 휴대폰을 세로로 들면 화면이 1/3 크기 | 세로 안내 없음 → 세로로 든 터치 기기에 '가로로 돌리기' 쪽지(이대로 할래요 가능) |
| **(터치)** 길게 눌러 세게 치면 메뉴·글자 선택이 뜸 | `contextmenu` 막기 + `-webkit-touch-callout:none`·`user-select:none` |
| **(터치)** 누른 단추가 들린 채로 남음 | `:hover` 효과가 터치 뒤 붙어 있음 → `@media (hover:hover)` 안에만 |
| 실험 소품을 마구 연타하면 통과 (울림 밴드) | 판정을 0.25초 미뤄 두는 동안 다른 입력도 받음 → 판정 대기 중(`pend`)과 오답 대기 중에는 입력 무시 |
| 대기 시간이 끝났는데 보기가 안 눌리는 것처럼 보임 (시험용 2560 화면) | 시험 브라우저가 2D 게임에도 소프트웨어 WebGL을 켜서 한 장면에 0.3초 → 게임 시간이 느리게 흐름. `game-verify`는 3D 게임에만 켠다. 기다림이 시간 초과되면 조용히 넘어가지 말고 보고 |
| 빨리 감기로 촬영하자 '느려서 효과를 줄였어요' 알림이 문제를 가림 | 자동 저사양 감시가 빨리 감기를 느린 화면으로 착각 → 촬영·점검 때는 `__test.quiet()`로 감시를 끈다 |
| 결과 화면 뒤로 지도 글자가 비침 | 반투명 결과 화면 아래 다른 DOM 화면이 열려 있음 → 결과를 열 때 다른 화면을 모두 닫는다 |
| **(그림)** 소리굽쇠 손잡이를 물에, 우쿨렐레 몸통 거꾸로, 같은 길이 건반이 다른 높이, 고무줄을 채로 침, 방음벽이 찻길 한가운데, 실 전화기 실이 바닥색에 묻힘, 음판 색이 '높게' 표시색과 같아 정답 단서 (울림 밴드) | 글만 감사하고 그림은 안 봄 → 모든 문항·단계 사진을 `content-critic`에게 넘겨 그림까지 교과 사실과 대조 |
| **(용어)** 공연 기능 이름 '메아리'가 단원의 메아리(소리의 반사)와 다른 뜻 | 게임 속 이름을 지을 때 단원 용어 목록과 겹치는지 본다 |
| 그림 이름표가 인물 얼굴을 가리거나 화면 아래에서 잘림 | 이름표 위치를 고정값으로 둠 → 문항 사진에서 이름표마다 가림·잘림 확인 |

## 3. 검증 도구 (Claude Code 환경)

- **Playwright + Chromium:** `executablePath:'/opt/pw-browsers/chromium'`, `NODE_PATH=/opt/node22/lib/node_modules`.
- **빠른 시뮬레이션:** `page.evaluate`로 게임 함수를 직접 부른다. 루프를 끄고 `update(1/60)`을 반복한다.
- **한 번에 돌리는 자동 점검: `game-verify` 스킬** (`.claude/skills/game-verify/`)
  - 게임에 점검 창구 `window.__test`(스킬 1장)를 넣고 `node .claude/skills/game-verify/scripts/verify.js "<게임.html>" <scratchpad 폴더>`.
  - 정적 검사, 전 문항·단계 사진과 문항 감사(정답 위치 섞임·글 넘침 포함), 자동 플레이 3종, **기기 13종 실제 터치·마우스**(시작·오답 힌트·정답·연타 통과·새 보기 보호·멈춤·소리·세로 안내·길게 누르기)를 한 번에 보고 `PASS`/`FAIL n건`을 낸다.
  - 문항 사진 모음(`content/sheet_*.png`, `items.json`)은 **`content-critic`**에게 넘겨 그림·글의 교과 정확성을 본다.
- **꼭 확인할 것 (game-verify가 잡지 못하는 것 포함):**
  - `game-verify` PASS, `content-critic` "반드시 고칠 것" 0건
  - 기기별 사진(`devices/`)을 직접 열어 글이 너무 작거나 가리는 곳이 없는지
  - 프레임 시간
  - 다시 시작할 때 초기화
  - 상점·저장이 있으면 그 동작
  - ESLint `no-undef`
  - 허브 테스트
  - **스크린샷을 직접 보고 판단**
  - **그래픽 채점:** 가이드 9장 "넘길 것" 세트(타이틀 · 플레이 대기 0·0.5·1초 3장 · 정답 순간 · 오답 + 힌트 · 결과 · 저사양 1장)와 스타일 카드를 `art-critic` 서브에이전트에게 넘겨 채점표(그래픽 가이드 9장) 모든 항목 4점 이상 + 스타일 관문(계열 돌려쓰기·6축)
  - **연출 점검:** 정답·오답·스테이지 열림·완주 사건의 연속 스크린샷(0/0.2/0.5/1초)과 HTML 경로를 `juice-critic`에게 넘겨 `docs/연출_점검.md` 양식으로 받고, 1번 항목과 "깎을 것"을 반영
  - **저사양:** CPU 4배 느리게(`Emulation.setCPUThrottlingRate`)에서 저사양 모드가 끊기지 않는지
  - **이모지 검사:** 게임 화면 코드에 이모지가 없는지 정규식으로 확인(허브 `index.html` 아이콘은 예외)
- 테스트는 통과했는데 화면이 밋밋하면 그것도 결함이다. 품질 목표(`CLAUDE.md` 2장)와 그래픽 가이드 9장으로 비교한다.

## 4. 저장소 규칙 · 배포

- **파일명:** `N학년 N학기 과목 단원 주제(게임 이름).html`
  - 한글은 NFC로 저장한다(NFD면 GitHub Pages에서 404).
  - 이름을 바꿀 때는 `git mv`를 쓴다. 같은 게임을 두 이름으로 두지 않는다. 예전 이름이 이미 공유됐으면 그 이름에는 새 주소로 옮겨 주는 작은 파일만 남긴다(`tank.html`, `baram.html` 등이 그 예).
- **사이트에 올리지 않는 것:** `_config.yml`의 `exclude`에 적은 폴더는 GitHub Pages에 올라가지 않는다. 지금은 `release/`(정답표·answers.json·소개글·게시판 사진)를 막아 두었다. 저장소에는 그대로 있다.
- **허브 등록:** `index.html`의 `const FALLBACK = { version: N, games: [ … ] }` 목록에 한 줄을 넣는다(한 줄에 게임 하나). 같은 날 `docs/그래픽_기록.md`의 두 표(9가지 표는 시안 줄 아래, 계열·6축 표는 맨 위)에 이 게임 줄을 더하고 "다음 게임의 제외 계열"을 다시 계산한다.
  - 새 항목: `{"id":(최대 id+1),"icon":"이모지","title":"N학년 N학기 과목 …(게임 이름)","url":"./파일명.html","unit":단원번호,"tags":["핵심어",…]}`
    - `unit`: 게임 파일에 적힌 단원 번호(숫자). 카드에 "2단원"으로 보이고 "2단원"으로 검색된다. 모르면 넣지 않는다.
    - `tags`: 검색용 핵심어 4~8개. 제목에 없는 학습 낱말(예: 고조선, 기압, 반지름)을 문항에서 골라 넣는다.
    - 고를 때만 쓰는 칸: `name`(카드 큰 글씨를 제목과 다르게), `game`(카드 둘째 줄, 기본은 제목 괄호 안 게임 이름), `series`+`ep`(여러 편을 카드 1장으로 묶기), `net:1`(인터넷 글꼴·도구가 있어야 제대로 보이는 옛 게임), `thumb`(썸네일 경로를 따로 줄 때).
  - **썸네일:** `NODE_PATH=/opt/node22/lib/node_modules node tools/hub/make_thumbs.js <id>`로 `thumbs/<id>.webp`(480×270)를 만든다. 3D 게임도 찍히도록 소프트웨어 WebGL로 연다. 소프트웨어 렌더는 느려 타이틀 연출이 덜 끝나 보이면 `PREP_BY_ID`에 `'gametime'`(게임 안 시간 `GAME.T`가 4초를 넘을 때까지 기다림)을 단다. 허브는 이 파일을 자동으로 쓰고, 없으면 이모지를 보여 준다. 첫 화면이 작은 상자뿐이면 스크립트의 `PREP`에 시작 단추 누르기를 더한다.
  - 허브는 title 앞부분의 "N학년 N학기 과목"으로 분류하므로 이 순서를 지킨다. 학년 안에서 학기별로 묶이고(지금 학기는 펼치고 다른 학기는 접힘), 창체 게임은 학년과 상관없이 '놀이·창체' 칸에 모인다.
  - 목록은 학년 → 학기 → 과목 → 제목 순서로 넣는다.
  - `version`을 1 올리고, `<meta>` 설명의 게임 개수도 맞춘다.
  - 교사가 GitHub 웹에서 `index.html`을 직접 고치기도 한다. **수정 전에 최신 main을 가져온다.**
  - 링크 미리보기 그림 `og.png`(1200×630)는 `tools/hub/make_og.js`로 만든다. 게임 개수를 그림에 넣지 않으므로 새 게임마다 다시 만들 필요는 없다.
  - 공개 화면에는 관리자 단추가 없다. 주소 끝에 `#admin`을 붙이면 관리자 창이 열리고, 여기서 고친 내용은 그 브라우저에만 보인다(모두에게 반영하려면 "목록 코드 복사" 후 `FALLBACK`을 바꿔 커밋).
  - 게임 실행 화면은 위쪽 막대(새 창 · 전체 화면 · 내려받기 · 닫기) 아래에 게임을 연다. 게임 오른쪽 위 단추가 허브 단추에 가리지 않는다.
  - 첫 화면의 오른쪽 그림(3장)과 '새로 나온 게임' 줄(4장)은 id가 큰 게임을 자동으로 보여 주고, 목록 카드에는 id가 큰 6개에 NEW가 붙는다. 새 게임을 등록하고 썸네일만 만들면 따로 고칠 것이 없다.
  - 허브 글꼴: 큰 한글 제목은 Black Han Sans(Google Fonts), 한글 본문은 Pretendard(jsDelivr), 영문·숫자는 Archivo·Inter. 모두 OFL이며, 못 불러오면 기기 글꼴로 보인다(게임 파일의 '인터넷 없이' 규칙은 허브에는 해당하지 않는다).
- **배포:** 작업 브랜치 커밋 → push → PR → main 병합(= 배포). 이전 PR이 병합됐으면 브랜치를 최신 main에서 다시 시작한다.

## 5. 과목·학습 내용과 장르 궁합

장르 추천 전에 이 단원의 문제가 어떤 모양인지 먼저 본다. 아래는 출발점이고, 더 잘 맞는 짝이 있으면 그걸 쓴다.

| 문제 모양 | 잘 맞는 장르 | 조심할 점 |
|---|---|---|
| 긴 지문을 읽고 고르기 (국어 독해, 사회 자료 해석) | 턴제 전략·보드·카드 대결, 방탈출·추리, 낚시(기다리는 시간), 디펜스(웨이브 사이에 읽기), 이야기·시뮬레이션 | 피하면서 읽어야 하는 실시간 액션은 맞지 않는다. 지문은 멈춘 화면·쉬는 방에서 읽게 한다. |
| 짧은 계산·판단을 빠르게 반복 (연산, 어림, 크기 비교) | 로그라이크(정답 보상으로 스킬·능력 업그레이드), 서바이벌, 러너, 리듬, 레이싱 | 아무 보기나 빨리 눌러도 되는 구조는 안 된다. 오답에는 시간·체력 손해를 준다. |
| 각도·거리·위치·방향 (도형, 측정, 지도, 비와 비율) | 포격(각도·힘), 운전, 골프·당구 같은 물리 스포츠, 배치형 디펜스, 건설 | 손 기술이 아니라 계산·판단으로 맞히게 한다(값을 입력하거나 고르면 그대로 날아가는 식). |
| 분류·짝짓기·순서 (용어, 시대 순서, 개념 분류) | 퍼즐, 분류 공장·물류, 카드 덱 만들기, 리듬 | 보기 수가 적으면 찍기로 통과된다. 한 번에 여러 개를 맞혀야 넘어가게 한다. |
| 변인·원인과 결과 (과학 실험) | 샌드박스 실험, 건설·경영, 시뮬레이션 | 실험 결과를 보고 고르게 하되, 화면 구성이 "장면 + 문제 카드"로 굳지 않게 한다. |
| 낱말·철자·문법 (국어 문법, 영어 단어) | 타자 디펜스, 낱말 퍼즐, 리듬 | 타자 실력 차이가 너무 크면 터치용 선택 방식을 함께 둔다. |

**저장소에 이미 있는 장르** (같은 장르를 다시 써도 되지만 핵심 조작·화면 구성·그림체는 달라야 한다):
디펜스(동그라미 왕국 수비대, 우주 디펜스, 합리적 소비 디펜스), 서바이벌(다각형·비와 비율), 러너(달려라 경제 쿠키, 에듀런), 플랫포머(마리오), 탱크, 축구 패널티킥, 추격전, 테트리스 퀴즈, 경영·건설(코스터 타이쿤, 분수 베이커리, 텃밭, 택배 물류센터, 고려 활자 인쇄소), 이야기·시뮬레이션(날씨 상자 실험실, 어린이 방송국, 천지인 메신저), 타자(낱말 방어선), 카드 대결(인터뷰 카드 배틀), 스포츠(분수 컬링), 기차 운행(분수 급행열차).
